# Testing strategy

Tests are written before the code they test. A change without a test that failed first is
not reviewable. Coverage on `src/` must stay at or above 85 %; the number is a floor, not a
target.

## Tiers

| Tier | Location | Proves | Runs |
|---|---|---|---|
| Unit | `tests/unit/` | One function or class behaves per its docstring, including edge cases | every push, all Python versions |
| Contract | `tests/unit/test_*_contract.py` | A cross-cutting contract holds (logging fields, exit codes, settings validation) | every push |
| Golden | `tests/golden/` | A documented input produces a byte-identical or field-identical output (format round-trips, reports, manifests) | every push |
| Parity | `tests/parity/` | A metric or transformation matches a reference implementation within a stated tolerance | nightly or on touch |
| Chaos | `tests/chaos/` | The system survives interrupted writes, truncated files, killed processes | nightly or on touch |
| Benchmark | `benchmarks/` | A performance budget is met on a named reference input | manual, before release |

A tier directory is created the moment the first test of that tier exists; empty
directories are not committed.

## Rules

- Unit tests make no network calls, read no files outside `tmp_path`, and do not depend on
  wall-clock time or environment variables unless the test sets them.
- Test names state the behaviour: `test_redacts_nested_authorization_header`, not
  `test_redact_2`.
- Assert behaviour, not implementation. A refactor that keeps behaviour must not break a
  test.
- Every bug fix adds the test that would have caught it.
- Edge cases are the default checklist: empty input, one element, invalid input, unicode,
  very large input, non-serialisable values, interrupted I/O, concurrent access where
  relevant.

## Fixtures

- Small synthetic fixtures live next to the tests. Anything over 100 KB is generated by a
  script in `tests/fixtures/` at test time.
- Fixtures never contain real personal data, real credentials or real customer images.
  Fake secrets used to test redaction are obviously fake (`"token": "not-a-real-token"`).

## Parity and chaos specifics

- Parity tests pin the reference implementation's version and record the tolerance in the
  test. A tolerance change is a reviewed decision.
- Chaos tests simulate `kill -9` mid-write by writing to a temporary path and asserting the
  recovery routine ignores the partial file.

## What CI runs

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=datacopilot --cov-fail-under=85
```

Parity, chaos and benchmark tiers are selected with pytest markers (`-m parity`, `-m chaos`)
and excluded from the default run once they exist.

## Documentation and release tests

- `tests/docs/` executes the tutorial and the Python API page (every `<!-- run -->` block; output is
  compared with the page, `...` and `<uuid>` are wildcards), requires every command block of a user page
  to be executed or marked `<!-- skip: reason -->`, checks the generated CLI reference for drift and, with
  the `docs` dependency group, builds the site in strict mode and scans it for remote assets.
- `tests/release/` lints every workflow (pinned actions, no expression in a script, permissions, trigger
  and job separation of the release), and, with the `release` dependency group, builds the wheel and the
  sdist, asserts their contents and metadata and installs the wheel in a clean environment.
  `uv run --group docs --group release pytest` runs everything.
- `tests/release/test_clone.py -m clone` (or `scripts/check_clone.sh [PYTHON]`) clones the committed
  HEAD, installs it from the lock file (`uv sync --frozen --no-dev`) into an empty environment and runs
  `--version`, `doctor` and the README quick start. It needs git, uv and the network for the dependencies,
  so it is off by default.
