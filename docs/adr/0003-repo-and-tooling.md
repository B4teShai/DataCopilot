# ADR-0003: Repository, packaging and quality tooling

**Status:** accepted
**Date:** 2026-10-14

## Context

DataCopilot is an installable Python package that must work on CPU-only laptops and CI
runners, be easy to contribute to, and keep a strict quality bar from the first commit. It
is developed alongside a sibling project with the same conventions.

## Options considered

### Option A: monorepo with both projects

Trade-offs: one CI, shared tooling; but coupled release cycles, one issue tracker for two
products, and a heavier clone for users of one package.

### Option B: independent repositories with mirrored conventions

Trade-offs: each project releases and is adopted on its own; conventions can drift unless
they are generated from one source.

### Packaging: setuptools vs hatchling; pip-tools vs uv

Trade-offs: hatchling has a smaller configuration surface and native `src/` support; `uv`
gives a committed lockfile and fast, reproducible installs in CI.

## Decision

Option B, independent repositories. Conventions are generated from a shared template so
they stay mirrored by construction.

- Python ≥ 3.10; `src/` layout; hatchling build backend; `uv` with a committed `uv.lock`;
  CI installs with `uv sync --locked`.
- Core runtime dependencies: `typer`, `click`, `pydantic` (v2), `structlog`, `pyarrow`
  (Parquet tables of the dataset store, [ADR-0006](0006-dataset-format.md); Apache-2.0), `numpy`
  (vectorised box and count arithmetic in the audit checks, BSD-3-Clause) and `jinja2` (the HTML
  report template, BSD-3-Clause; brings `markupsafe`).
  Anything heavier (PyTorch, Polars, FastAPI, database drivers) arrives only behind an
  optional extra. The core wheel stays CPU-only and torch-free. DuckDB is still not a core
  dependency: the Phase 2 audit reads the tables through the bounded store reader and works on
  NumPy arrays, so it is added only with the first feature that needs SQL over the tables.
- `numpy` and `jinja2` were added with the first audit checks and the report generator (Phase 2).
  `numpy` is needed because per-annotation Python loops over 500,000 boxes miss the audit budget
  ([standards.md](../engineering/standards.md), "Performance habits"); `jinja2` is used with
  autoescaping always on, so report text from untrusted datasets cannot inject markup. Measured
  installed-size delta on Python 3.13, macOS arm64: `numpy` 21.6 MB, `jinja2` and `markupsafe`
  0.6 MB, so the core install is about 162 MB against the 250 MB budget. Neither package pulls
  `torch` or a CUDA library.
- `pyarrow` has no mandatory dependencies of its own on current releases, so Phase 1 grew the
  core install by one wheel and Phase 2 by `numpy`, `jinja2` and `markupsafe`; the installed-size budget in
  [../architecture/01-overview.md](../architecture/01-overview.md) is measured in CI-style
  checks and stays at or below 250 MB.
- Development-only dependencies: `pytest`, `pytest-cov`, `ruff`, `mypy`, `hypothesis`
  (property tests for geometry and hashing).
- XML (Pascal VOC) is parsed from standard library `expat` events (`xml.parsers.expat`, tree
  built with `xml.etree.ElementTree.TreeBuilder`) with handlers that reject any document type
  declaration and entity declaration, so external and internal entities are never resolved,
  and with a nesting limit. `defusedxml` is not a dependency. YAML (`data.yaml`) is read by a
  restricted subset parser in the package; no YAML library is a dependency.
- Quality gate on every push: `ruff check`, `ruff format --check`, `mypy --strict` on
  `src/`, `pytest` with coverage ≥ 85 %, on Python 3.10 to 3.13.
- Diagrams: `.excalidraw` sources plus PNG with the scene embedded, generated by scripts
  from the workspace toolchain. Outside the workspace the `.excalidraw` files are edited
  directly.

## Consequences

- Adding a core dependency is a visible, reviewed change to this ADR and `pyproject.toml`.
- Contributors need `uv`; nothing else beyond a supported Python.
- The two projects share no code at runtime; shared contracts (for example the dataset
  version hash) are documented, not imported.
